# HERO_ANIMATION.md

## Цель

Главный экран должен визуально показывать процесс:

**код → работающий веб-интерфейс**

Анимация должна создавать ощущение, что разработчик не просто пишет код, а превращает его в готовый цифровой продукт.

---

## Сценарий

### Состояние 1 — «Код»

При загрузке страницы пользователь видит только код.

Код занимает основную визуальную область первого экрана и выглядит как настоящий исходный код веб-интерфейса.

Не использовать оформление обычного терминала:
- без окна терминала;
- без зелёного текста;
- без имитации командной строки;
- без декоративного программного кода.

Код должен выглядеть как часть самого интерфейса сайта.

---

### Состояние 2 — «Трансформация»

Код начинает изменяться.

Отдельные строки, блоки и структуры кода постепенно превращаются в визуальные элементы будущего интерфейса:

- контейнеры → области интерфейса;
- переменные → значения;
- структуры → блоки;
- кнопки в коде → реальные кнопки;
- данные → содержимое;
- стили → визуальное оформление.

Переход должен быть непрерывным.

Нельзя делать резкое исчезновение кода и появление готового сайта.

---

### Состояние 3 — «Готовый продукт»

Из кода полностью формируется веб-интерфейс.

На экране появляется законченный современный интерфейс цифрового продукта.

Интерфейс должен выглядеть функциональным и реалистичным, а не как декоративный макет.

Допускаются:
- панели;
- таблицы;
- графики;
- формы;
- кнопки;
- списки;
- показатели;
- навигация.

---

## Визуальная логика

Главный принцип:

**каждый элемент интерфейса должен визуально иметь происхождение из кода.**

Зритель должен понимать трансформацию даже без текста:

`CODE → UI`

Не использовать отдельный экран «до» и «после».
Это одна непрерывная сцена.

---

## Анимация

Анимация умеренная и плавная.

Приоритет:
1. трансформация формы;
2. движение элементов;
3. появление структуры интерфейса;
4. затем вторичные детали.

Не использовать:
- глитч;
- вспышки;
- взрывы частиц;
- сильное свечение;
- постоянное движение;
- резкие переходы.

Анимация должна выглядеть как интеллектуальная сборка продукта, а не как спецэффект.

---

## Повторение

После завершения трансформации интерфейс остаётся на экране.

При повторном запуске сценарий проходит снова:

**код → трансформация → готовый интерфейс**

Повторение должно быть достаточно редким, чтобы не раздражать пользователя.

---

## Интерактивность

При движении курсора допускается небольшая реакция интерфейса.

Курсор не должен запускать хаотичные эффекты.

Интерактивность должна усиливать ощущение работающего продукта.

---

## Ограничения

- Не использовать фотографию человека.
- Не использовать неон.
- Не использовать киберпанк.
- Не использовать стеклянные карточки.
- Не использовать банальный терминал.
- Не перегружать экран кодом.
- Не превращать анимацию в самостоятельный аттракцион.
- Код и интерфейс должны оставаться читаемыми.
- Анимация не должна мешать основному продающему сообщению.

## Критерий готовности

Если пользователь посмотрел на анимацию 2–3 секунды, он должен однозначно понять:

**«Этот разработчик превращает код в готовые цифровые продукты».**

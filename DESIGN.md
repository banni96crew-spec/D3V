# DESIGN.md

## Назначение

Этот файл — единый источник правды для визуального дизайна проекта D3V.

Весь проект верстается строго по этим правилам.
Любое отклонение от указанных токенов, сетки, типографики, карточек или анти-паттернов считается дефектом и должно быть исправлено.

---

# 1. Запретный список — Anti-Slop

| Запрещено | Правило |
|---|---|
| Неон | Не использовать яркое неоновое свечение и кислотные акценты. |
| Киберпанк | Не использовать HUD, глитч, футуристические рамки и декоративный sci-fi. |
| Стеклянные карточки | Не использовать glassmorphism, сильное размытие фона и прозрачные панели. |
| Градиентный шум | Не использовать декоративные градиенты без функциональной причины. |
| Бессмысленный код | Код должен иметь визуальную или смысловую функцию, а не быть декорацией. |
| Банальный терминал | Не использовать стандартное окно терминала как главный визуальный приём. |
| Огромные фотографии | Первый экран не строить вокруг фотографии разработчика. |
| «AI-slop» | Не использовать шаблон: тёмный фон + фиолетовый градиент + стеклянные карточки + свечения. |
| Перегруженность | Один экран — одна главная визуальная идея. |
| Декоративные элементы | Не добавлять элементы только ради заполнения пустого пространства. |
| Слишком много цветов | Основная палитра ограничена фоном, текстом и 1–2 акцентами. |
| Случайные радиусы | Радиусы должны соответствовать системе проекта. |
| Случайные размеры | Размеры текста и элементов берутся только из утверждённой шкалы. |

# 2. Референсы

## Реф 1 — OpenCode

https://opencode.ai/ru

Используется как основной визуальный ориентир проекта.

Ключевые принципы:
- минималистичная композиция;
- сильная типографика;
- тёмная технологичная основа;
- продукт является частью визуального языка;
- минимум декоративных эффектов.

## Реф 2 — Warp

https://www.warp.dev/

Используется как дополнительный ориентир для:
- демонстрации рабочего интерфейса;
- связи дизайна сайта с самим продуктом;
- использования технических элементов как части брендинга.

## Реф 3 — Анатомия метрик

Использовать как ориентир для построения информационных карточек с метриками.

Правило:
карточка должна иметь понятную структуру:

1. название метрики;
2. главное значение;
3. изменение / пояснение;
4. дополнительный контекст.

Не превращать метрику в декоративный элемент.

# 3. Бенто

Бенто-композиция разрешена **только для избранных карточек**.

Референс: **Реф 1 — OpenCode**.

Запрещено превращать весь интерфейс в сетку одинаковых бенто-карточек.

Бенто используется только там, где группировка нескольких связанных элементов действительно улучшает понимание информации.

Правила:
- разные размеры блоков допускаются;
- каждый блок должен иметь смысл;
- карточки не должны выглядеть одинаковыми;
- нельзя добавлять карточку только ради заполнения сетки;
- визуальный вес карточек должен соответствовать важности информации.

# 4. Цветовые токены

## Основные

```css
--color-bg: #0B0D10;
--color-surface: #12161C;
--color-surface-elevated: #181D24;

--color-text-primary: #F2F4F7;
--color-text-secondary: #8E99A8;
--color-text-muted: #5E6875;

--color-border: #252B34;

--color-accent: #4C8DFF;
--color-accent-secondary: #5FC6D6;
````

## Правила

* Фон — преимущественно `--color-bg`.
* Основной текст — `--color-text-primary`.
* Второстепенный текст — `--color-text-secondary`.
* Акцент используется точечно.
* Одновременно не использовать несколько конкурирующих акцентных цветов.
* Не использовать яркое свечение акцентного цвета.
* Не добавлять новые цвета без необходимости.

# 5. Типографика

Основной шрифт:

**Inter** или визуально максимально близкий современный гротеск.

## Шкала

```css
--text-xs: 12px;
--text-sm: 14px;
--text-md: 16px;
--text-lg: 18px;
--text-xl: 20px;

--text-2xl: 24px;
--text-3xl: 32px;
--text-4xl: 40px;
--text-5xl: 48px;
--text-6xl: 64px;
--text-hero: 80px;
```

## Начертания

```css
--weight-regular: 400;
--weight-medium: 500;
--weight-semibold: 600;
--weight-bold: 700;
```

## Правила

* Заголовки — преимущественно 600–700.
* Основной текст — 400–500.
* Не использовать конденсированные шрифты.
* Не использовать более двух шрифтов в проекте.
* Не использовать декоративные шрифты.
* Заголовок должен иметь очевидный визуальный приоритет.

# 6. Сетка

Базовая единица:

**8 px**

```css
--space-1: 8px;
--space-2: 16px;
--space-3: 24px;
--space-4: 32px;
--space-5: 40px;
--space-6: 48px;
--space-8: 64px;
--space-10: 80px;
--space-12: 96px;
--space-16: 128px;
```

## Desktop

* максимальная ширина контента: 1440 px;
* боковые поля: минимум 40 px;
* основная сетка: 12 колонок;
* межколоночный интервал: 24 px.

## Mobile

* боковые поля: 20 px;
* межколоночный интервал: 16 px;
* использовать 4-колоночную сетку.

# 7. Карточка

## Анатомия

Карточка должна состоять только из необходимых элементов:

```text
┌─────────────────────────────┐
│ LABEL / CATEGORY             │
│                             │
│ Главный показатель          │
│                             │
│ Краткое пояснение           │
│                             │
│ Дополнительный контекст     │
└─────────────────────────────┘
```

Для карточек метрик использовать **Реф 3**.

## Токены

```css
--card-padding: 24px;
--card-radius: 12px;
--card-border: 1px solid var(--color-border);
--card-bg: var(--color-surface);
```

## Правила

* Одна карточка — одна смысловая единица.
* Главный показатель визуально доминирует.
* Вторичный текст заметно слабее.
* Не использовать декоративные изображения без функции.
* Не использовать сильные тени.
* Не использовать стеклянный эффект.
* Не использовать одинаковые карточки для всей страницы.

# 8. Анимация

Анимация должна объяснять действие или состояние.

Допустимо:

* плавное появление;
* изменение состояния;
* сборка интерфейса;
* движение элементов кода;
* реакция на наведение;
* постепенная трансформация кода в продукт.

Запрещено:

* постоянное вращение;
* бесконечный глитч;
* резкие вспышки;
* чрезмерное параллакс-движение;
* анимация каждого элемента страницы.

# 9. Главный экран

Главная визуальная идея:

**код → готовый цифровой продукт**

Код является частью интерфейса, а не декоративным фоном.

Композиция должна создавать ощущение процесса:

1. структура и код;
2. преобразование;
3. готовый интерфейс;
4. законченный продукт.

Первый экран продаёт разработчика.
Результаты конкретных проектов показываются ниже.

Основной призыв:

**Обсудить проект →**

# 10. Критерий проверки

Перед завершением каждого экрана проверить:

* используется ли утверждённая палитра;
* используется ли утверждённая типографика;
* соблюдается ли сетка 8 px;
* соблюдаются ли размеры и отступы;
* нет ли запрещённых анти-паттернов;
* имеет ли каждый декоративный элемент функцию;
* не перегружен ли экран;
* соответствует ли композиция референсам;
* используется ли бенто только там, где оно действительно необходимо;
* соответствует ли анатомия карточек Реф 3.
